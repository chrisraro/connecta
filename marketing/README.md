# Connecta — Marketing Assets

Everything a printer, a designer, or a deck needs to reference Connecta's
brand and product, without touching the running app.

```

├── README.md              this file
├── brand/
│   ├── sigmatap-mark.svg   the monogram (copy of public/brand/sigmatap-mark.svg)

│                           the type scale, correct/incorrect usage
└── mockups/                generated PNG screenshots of the live product
    └── generate-mockups.mjs (see below — script lives at marketing/ root)
```

## Brand basics

**The mark.** A solid Greek sigma (Σ) — pairing "sum" with the product's
core action, the NFC tap: every tap sums into a shareable profile and a
captured lead. Deliberately has **no radiating NFC arcs**: three variants
pairing the sigma with arcs were rendered and compared at 150px/48px/20px,
and the arcs read as "3" or a mirrored sigma at large size and collapsed to
an unreadable blob below ~34px. Radiating arcs are also the digital-business-
card category's commodity signifier (Popl, Blinq, Tapik, TapiTag all use
them) — the solid counter-form alone carries the identity instead. Drawn as
a single SVG path in `currentColor` so it inherits from any surface and
never needs a recolour pass.

**The seal.** The app icon is the same sigma struck *into* a wax seal —
the disc and the monogram are subpaths of one `fill-rule="evenodd"` path, so
the knockout is real transparency rather than a shape sitting on top of a
circle. That negative-space relationship is the point: it's what stops the
icon from reading as "a logo on a coloured circle."

**Palette.** One saturated brand colour carrying real surface area (the
seal), plus warm neutrals tinted toward that same hue rather than generic
warm-gray, and the light/dark app surface pair. Hex values below are the
computed sRGB output of the OKLCH tokens in `app/globals.css` (read live via
a headless-browser canvas conversion — OKLCH doesn't have one canonical hex,
so these are what actually renders).

| Name | Hex | Token |
|---|---|---|
| Seal | `#8d2c27` | `--connecta-brand` |
| Seal — hover | `#7f1817` | `--connecta-brand-hover` |
| Ink | `#201916` | `--connecta-ink` |
| Ink — soft | `#5f5652` | `--connecta-ink-soft` |
| Paper | `#fcfaf8` | `--connecta-paper` |
| Surface | `#f5f1ef` | `--connecta-surface` |
| Line | `#e3ddd9` | `--connecta-line` |
| Background — light | `#fbfaf7` | `--background` (`:root`) |
| Foreground — light | `#100d09` | `--foreground` (`:root`) |
| Background — dark | `#030609` | `--background` (`.dark`) |
| Foreground — dark | `#f0f6fa` | `--foreground` (`.dark`) |

**Type stack.** Fraunces (display) + Geist (body) carry the app shell. Each
of the three profile templates loads its own display face instead, so
templates read as typographically distinct rather than "one design, three
colour schemes":

| Role | Face | Where |
|---|---|---|
| Display | Fraunces | Marketing headlines, hero copy |
| Body / UI | Geist | App shell, dashboard, forms (serif banned here) |
| Template — Editorial | Newsreader | Writers, consultants, photographers |
| Template — Kinetic | Space Grotesk | Developers, studios |
| Template — Architectural | Manrope | Executives, firms |

**Radius / elevation.** Exactly three radii and two elevations, everywhere —
`--r-sm` (6px), `--r-md` (12px), `--r-lg` (20px) or `rounded-full`; `--e-raised`
and `--e-overlay` for shadows. No arbitrary pixel radii, no `shadow-2xl`.

**Usage.** Single colour only — never a gradient fill, never dropped on a
busy photo/background without a legibility scrim. Never mirrored, skewed,
rotated, or otherwise distorted. See `brand/brand-sheet.html` §5 for the
correct/incorrect pairs.

## Regenerating

**`brand/brand-sheet.html`** is hand-authored, not generated by a script —
it inlines the hex values above directly. If a token in `app/globals.css`
changes, re-derive the hex values (open the running app in a browser,
`getComputedStyle(document.documentElement).getPropertyValue('--connecta-brand')`
for each token, then paint it to a `<canvas>` and read the pixel back — OKLCH
computed-style strings vary by browser and aren't hex, so don't hand-convert)
and update the swatches and inline SVGs in that file to match.

**`mockups/*.png`** are generated by `generate-mockups.mjs` (below) and are
committed so a fresh checkout has usable assets without a dev server. If the
UI changes meaningfully, re-run the script and commit the new PNGs.

### Running `generate-mockups.mjs`

The script uses Playwright to drive a real Chromium against the app's dev
server. Playwright is intentionally **not** a `package.json` dependency (this
branch's remit forbids touching that file) — install it locally first:

```sh
npm install --no-save playwright
```

Then, with the dev server running on port 3000 (`npm run dev`):

```sh
node marketing/generate-mockups.mjs
```

Output goes to `marketing/mockups/`. The script is idempotent — safe to
re-run any time — and captures:

1. **Landing hero** (`hero.png`) — the "/" page's hero section, phone-scale
   product preview included.
2. **Public profile pages**, one per template (`profile-editorial.png`,
   `profile-kinetic.png`, `profile-architectural.png`) — the internal
   `/marketing-preview/[templateId]` route, at phone width. That route
   renders the exact same `ProfileRenderer` every real customer's public
   page uses, fed a static demo persona (`components/marketing/demoProfile.ts`)
   instead of a live Convex record — reproducible on a fresh checkout with no
   seeded database, and never a real customer's data.
3. **Dashboard** (`dashboard.png`) and **profile builder with the inspector
   open** (`builder-inspector.png`) — these require a signed-in session. The
   script mints one via the Clerk Backend API (`CLERK_SECRET_KEY` from
   `.env.local`) against a dedicated, idempotent demo user
   (`connecta-marketing-demo@connecta.example`) and a Clerk *sign-in token*,
   the same ticket-based approach Clerk's own testing tools use — no real
   customer account is ever touched. If `CLERK_SECRET_KEY` isn't available
   the script skips these two captures and still produces the rest.

All captures are taken at 2x device scale factor for print/social quality.
